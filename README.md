# Podman `.deb` builds

Automated builds of [Podman](https://github.com/podman-container-tools/podman) as installable `.deb` packages for **Ubuntu 24.04**, **Ubuntu 26.04**, and **Debian trixie** on **amd64** and **arm64**. Packages are produced in Docker on native GitHub-hosted runners, smoke-tested, and published as [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository) in this repository.

Upstream source and release metadata come from [podman-container-tools/podman](https://github.com/podman-container-tools/podman). Debian packaging metadata is taken from Debian sid `.dsc` files and combined with the latest upstream tarball at build time; Debian trixie builds use sid Go build dependencies required by that packaging.

## What gets built

Each distro target produces a small stack of packages:

| Package | Role |
|---------|------|
| `golang-github-containers-common` | Shared container configuration |
| `netavark` | Container networking (required for Podman 6) |
| `aardvark-dns` | DNS for container networks |
| `podman` | Main CLI (plus `podman-remote` and `podman-docker` with default Debian names) |

The primary Podman binary package is renamed for clarity:

- `podman-ubuntu-24.04-{version}_amd64.deb` / `_arm64.deb`
- `podman-ubuntu-26.04-{version}_amd64.deb` / `_arm64.deb`
- `podman-debian-trixie-{version}_amd64.deb` / `_arm64.deb`

Companion `.deb` files keep their Debian architecture suffix (`_amd64`, `_arm64`); on release they are prefixed with the matrix id (for example `ubuntu-26.04-arm64-netavark_…_arm64.deb`) so every asset name is unique when all targets are uploaded together.

## GitHub Actions workflow

Workflow file: [`.github/workflows/build-podman-deb.yml`](.github/workflows/build-podman-deb.yml)

| Trigger | Behavior |
|---------|----------|
| Push to `main` / `master` | Build, test, and create or update a release |
| Pull request | Build and test only (no release) |
| `workflow_dispatch` | Full pipeline on demand |
| Weekly cron (Monday 06:00 UTC) | Rebuild when a new Podman release appears |

Pipeline stages:

1. **Resolve version** — Latest tag from `podman-container-tools/podman` via the GitHub API.
2. **Build** — Matrix over three distros × two architectures (`ubuntu-24.04-arm` runners for arm64, `ubuntu-24.04` for amd64), using `docker/Dockerfile.build` on the matching native platform.
3. **Test** — Install all `.deb` files from that matrix cell in a clean container and run `podman run` (Alpine smoke test).
4. **Release** — After tests pass (non-PR events): release notes from the upstream Podman changelog, tag `v{version}`, upload all `.deb` assets.

Release notes are generated by [`scripts/podman-release-notes.sh`](scripts/podman-release-notes.sh), which copies the upstream release body into a short intro section.

### Workflow permissions

The release job needs **Read and write** permissions for the `GITHUB_TOKEN` (Repository **Settings → Actions → General → Workflow permissions**).

## Installing from a release

1. Open the release tagged `v{podman-version}` (for example `v6.1.4`).
2. Download the `.deb` files for your distro **and CPU** (for example `ubuntu-24.04-amd64-*` or `ubuntu-24.04-arm64-*` companions, plus `podman-ubuntu-24.04-{version}_amd64.deb` or `_arm64.deb`).
3. On the target system:

```bash
sudo apt-get update
sudo apt-get install -y ./ubuntu-26.04-*.deb   # match your distro prefix
podman --version
```

Install every package from the same release and distro prefix together so dependencies match.

## Local build

Requires Docker.

```bash
export PODMAN_VERSION="$(./scripts/latest-podman-version.sh)"   # optional; defaults to latest
export DISTRO_SLUG=ubuntu-24.04                                 # used for podman .deb rename

docker build -f docker/Dockerfile.build \
  --build-arg BASE_IMAGE=ubuntu:24.04 \
  -t podman-deb-builder .

mkdir -p artifacts
docker run --rm \
  -e PODMAN_VERSION \
  -e DISTRO_SLUG \
  -e OUT_DIR=/artifacts \
  -v "$PWD/artifacts:/artifacts" \
  podman-deb-builder
```

Smoke test locally:

```bash
./scripts/test-install.sh ubuntu:24.04 ./artifacts
```

For Ubuntu 26.04, use `BASE_IMAGE=ubuntu:26.04` and `DISTRO_SLUG=ubuntu-26.04`. For Debian, use `debian:trixie-slim` and `DISTRO_SLUG=debian-trixie`.

## Repository layout

```
.github/workflows/build-podman-deb.yml   CI pipeline
docker/Dockerfile.build                  Per-distro build image
scripts/
  build-podman-stack.sh                  Orchestrates companion + Podman builds
  build-deb-from-dsc.sh                  Build from a Debian .dsc URL
  latest-podman-version.sh                 Query latest upstream tag
  rename-podman-debs.sh                  podman-{distro}-{version}.deb naming
  test-install.sh                        Docker install + run smoke test
  podman-release-notes.sh                Upstream changelog for GitHub releases
  prepare-release-assets.sh              Flatten artifacts for release upload
  enable-deb-src.sh                        Enable deb-src on Ubuntu/Debian
```

Builds skip upstream test suites (`DEB_BUILD_OPTIONS=nocheck`) to keep CI time reasonable; full compilation still takes a while.
